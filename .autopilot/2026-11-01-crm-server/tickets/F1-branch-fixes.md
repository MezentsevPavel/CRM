## Что должно заработать

Сервер не даёт ни одному сотруднику обойти права подделанным запросом: ни через служебные имена ключей, ни через адрес файла со скриптом, ни через поддельные отметки заявки на отправку, ни через запись от чужого имени. Восстановление копии не возвращает доступ уволенным. Ручные копии не вытесняют ночные.

## Из брифа, дословно

> «права проверяет сервер, файлы на сервере … ежедневные копии базы»

## Разделы спецификации

Истории 11–13, 16, 18, 23–24, 39, 41. Решения: «Права на запись — Guard», «Файлы», «Копии».

## Критерии приёмки (замечания ревью дословно)

- [ ] Безопасность · server/app.js:112, src/js/47-guard.js:29 · Проверка на `"__proto__"` ищет только буквальный текст в теле запроса; ключ, записанный как `"__proto__"`, её проходит, JSON.parse делает из него обычное поле. Воспроизведение: POST /api/changes с новым движением `{kind:"Приход", productId:"__proto__", qty:5}` — Guard.expected пишет в Object.prototype ядра сервера, после этого остаток клетки «_/_» любого товара меняется без движения. **Условие:** если после разбора JSON на любой глубине встречается ключ, `id` или `productId`, равный `__proto__`, `constructor` или `prototype`, — ответ 400. Тест: запрос выше даёт 400, и в ядре `({})['_\u0001_'] === undefined`.
- [ ] Безопасность · src/js/54-ships.js:447, src/js/71-attach.js:26,27,34,40, src/js/44-attach.js:19, server/files.js:120 · Строки `received.urls` подставляются в `<img src="${u}">` без esc; поле `url` у файла принимается с любой схемой. Воспроизведение: адрес фото `x" onerror="…"` в поставке или файл задачи с `url:"javascript:…"` — скрипт выполняется во вкладке директора. **Условие:** сервер отвечает 403 на запись, где `url` файла или элемент `received.urls` не совпадает с `^/api/files/fl[0-9a-f]{24}$` (сверить с настоящим форматом id файла сервера); в 54-ships:447 стоит esc(u). Тест: задача с `files[0].url='javascript:1'` и поставка с `received.urls=['x" onerror=1']` дают 403.
- [ ] Склад · src/js/47-guard.js:263-275, src/js/39-dispatch.js:68 · Флаги заявки `moved` и `landed` не связаны с движениями склада: заявка сразу с `moved:true` и строкой на 1000 шт. уменьшает «Свободно» у всех без записи в журнале; при смене этапа прочие поля не проверяются через Dispatch.canEdit. **Условие:** Guard отвергает заявку, у которой `moved` становится true без «Перемещения» по каждой строке в той же пачке; `moved` становится false без обратных движений; `landed` ставится иначе как этапом «Доставлена» с правом dispatch; меняются строки заявки, пока груз в пути. При смене stageId прочие поля меняются только при canEdit. Тест: новая заявка с `moved:true` без движений даёт 403; обычная отправка, доставка и возврат через настоящие функции `Dispatch` — по-прежнему проходят.
- [ ] Права · src/js/47-guard.js:216,223,281 · Запись без `by` принимается в ленте, делах и уведомлениях (проверка `x.by && x.by !== pid`); запись ленты 'reserve' принимается с чужим `by`. **Условие:** новая запись feed, acts или notes из браузера с `by ≠ pid` (в том числе пустым) — 403; исключение — запись 'reserve', если в той же пачке меняется резерв этой сделки. Системные уведомления сервера (sync.system) это не задевает. Тест: note без `by` — 403; настоящие действия ядра (комментарий, дело, резерв, уведомление при отгрузке) — проходят.
- [ ] Сохранность · server/backup.js:20,174 · Восстановление переписывает таблицу `users` из копии — отключённый после копии сотрудник снова входит. **Условие:** после restore тот, кто отключён в текущей базе, остаётся `disabled=1` и без сеансов. Тест: отключить, восстановить копию до отключения — вход даёт 401.
- [ ] Сохранность · server/backup.js:68-70 · prune считает все копии вместе: 30 ручных копий или восстановлений стирают все ночные. **Условие:** ручные копии и копии «перед восстановлением» не вытесняют ночные, 30 последних ночных хранятся всегда (ручных и «перед восстановлением» — не больше 30 своих). Тест: после 31 вызова make('manual') число ночных копий не изменилось.
