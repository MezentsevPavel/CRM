**Требования:** R01, R03, R04, R05, R06, R07, R17i, R20i, R22i, R16

**Зона:** `server/` (кроме `server/backup.js`) · `tools/vm-load.js` · `tests/load.js` (только переход на `tools/vm-load.js`, API не меняется) · `tests/server-*.test.js`
**Волна:** 2
**Ревью:** да — вход, пароли, сеансы
**Модель:** сильная

## Что должно заработать

`node server/main.js` поднимает CRM: отдаёт страницу с серверной меткой, держит одну базу в SQLite, впускает по логину и паролю. Каждому сеансу отдаёт его урезанное состояние. Пачки изменений принимает только после слияния и проверки прав, а всем остальным открытым сеансам за пару секунд сообщает, что есть новое. Номера записей раздаёт без повторов. Файлы хранит на диске и отдаёт только тем, кому можно. Напоминания о делах и «лид ждёт» сервер делает сам. Директора заводит команда, сотрудникам директор выдаёт пароли через API. Браузерной части в этом таске нет: проверяется через `fetch`.

## Критерии приёмки

- [ ] `createApp({ dataDir, port: 0 })` и `node server/main.js` стартуют; `GET /` отдаёт собранную страницу со вставленным `window.CRM_SERVER=1` на месте метки; первый старт создаёт базу из `seedBase()`; после `close()` и нового старта на той же папке все записи на месте
- [ ] `tools/vm-load.js` — общий загрузчик `src/js` в `node:vm`; `tests/load.js` и `server/runtime.js` пользуются им; все старые тесты зелёные
- [ ] Вход: верные логин и пароль — 200 и cookie `crm_sid` (`HttpOnly`, `SameSite=Lax`, `Secure` при `secureCookie`); неверный логин и неверный пароль — одинаковые 401 «Неверный логин или пароль»; 5 неудач по логину — 429 на 15 минут с `retryMin`; «Чужой компьютер» — cookie без срока и сеанс ≤ 12 ч; иначе — 30 дней с последнего захода; `POST /api/logout` закрывает сеанс
- [ ] Пароль хранится только как `scrypt` с солью в таблице `users`; ни хеша, ни соли, ни токенов нет в `GET /api/state`, логах и ответах; смена пароля требует старый, новый ≥ 8 символов; `mustChange` после выдачи пароля директором
- [ ] Любой запрос записи без `X-CRM: 1` — 403; без сеанса — 401
- [ ] `GET /api/state` = `Visible.of` для человека сеанса; `POST /api/changes`: правки разных полей одной записи из двух сеансов — обе сохранены; одно поле — 409 с именем того, кто изменил, и свежими документами; отказ `Guard` — 403, база не изменилась; пачка проводится целиком или никак; на каждую проведённую запись — строка `log`
- [ ] Сеанс B получает событие `seq` по `/api/events` не позже 5 с после пачки сеанса A и забирает изменение через `/api/sync`; запись, ставшая невидимой (сделку передали другому), приходит в `gone`
- [ ] `/api/ids`: два сеанса, параллельно берущие номера `Д-`, получают разные номера по возрастанию
- [ ] Файлы: загрузка ≤ `CRM_FILE_MAX_MB` (20) — на диск, в базе только описание; больше — 413 «Файл больше 20 МБ — не загружен»; скачать может загрузивший и тот, кто видит запись со ссылкой на файл; остальные — 403; ссылки `file_refs` обновляются при каждой пачке; брошенный файл старше 7 дней и удалённый из записи старше 30 дней стираются задачей обслуживания
- [ ] Раз в минуту сервер зовёт `Acts.notify` и `Leads.notifyWaiting` на своём состоянии и рассылает результат; при трёх открытых сеансах напоминание об одном деле одно
- [ ] API директора: задать логин, выдать пароль (новый, показывается один раз в ответе), отключить (сеансы закрыты сразу, вход — 401), завершить сеансы; не директору — 403
- [ ] Ревизия: `meta.rev` меньше `Store.REV` — миграции из `server/migrate.js` (реестр пуст) или отказ запуска с понятным текстом; данные не стираются никогда
- [ ] `node server/admin.js create-director` и `reset-password <логин>` работают (пароль вводится с клавиатуры без эха; для тестов — функции `admin`)
- [ ] `node tools/build.js && node --test tests/` — зелёный
