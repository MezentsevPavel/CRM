## Что должно заработать

Всё, на чём сервер и браузер будут держать одну базу, существует и проверено в ядре, без сети. Состояние режется на документы и собирается обратно. Две правки одной записи сливаются, если трогают разные поля, а на одном поле дают конфликт. Номера записей можно брать у внешнего поставщика. Для любого человека строится его урезанная копия состояния: только то, что он видит по праву, без чужих цен и уведомлений. Для любой пачки изменений сказано, имеет ли человек право её провести, а склад меняется только движением в журнале. Инженер больше не правит клиентов и не пишет в ленту сделки (G01). Есть чистая база без демо. Демо-прототип ведёт себя как прежде.

## Критерии приёмки

- [ ] `SERVER` объявлен в `00-util.js`: `load({ globals: { CRM_SERVER: 1 } })` даёт `true`, `load()` — `false`; в `src/page.html` есть ровно одна метка `<!--CRM-SERVER-->`, собранная страница от неё не меняет поведения
- [ ] `Docs.split(seed())` → `Docs.join` даёт то же общее состояние (без `LOCAL`, товары снимка каталога — как в `Catalog.pack`); `Docs.KEYS` покрывает все 29 общих ключей `S` (тест падает, если в `seed()` появится неклассифицированный ключ)
- [ ] `Docs.diff` находит новые, изменённые и удалённые документы и ничего лишнего; `Docs.merge`: разные поля одной записи — обе правки в результате; одно поле изменено по-разному — `{ ok: false, path }`; массив записей с `id` — добавления с обеих сторон сохраняются
- [ ] `Ids.use(fn)` — `Store.freeId`, `Leads.nextId`, `Dispatch.nextNumber` и номер поставки `П-` (вынесен из вида в функцию) берут номер у поставщика; `Ids.use(null)` — номера как раньше (старые тесты зелёные)
- [ ] `Visible.of(seed(), pid)` для каждого из 9 ролей демо: нет сделок вне `Leads.dealsVisible`, лидов вне `Leads.visible`, клиентов вне `Visible.client`, задач вне `Visible.task`, чужих уведомлений (у `firm` — все), цен без `prices`, номера невидимой сделки у резерва (`'hidden'`, `Stock.reserveView` → «сделка скрыта»); `mail`, `msgs` пусты; `prefs` — только свои строки; исходное состояние не изменено
- [ ] Для каждой роли: страница, поднятая на `Visible.of(seed(), pid)` с `S.me = pid`, рисует каждый свой раздел `NAV` и открывает карточку каждой видимой сделки, клиента, задачи, поставки без исключений
- [ ] `clientVisible` и `taskVisible` перенесены в `Visible.client`/`Visible.task`; виды зовут их, второй копии условий нет
- [ ] `Guard.check` по каждой строке таблицы `interfaces.md` — тест «можно» и тест «нельзя» с текстом «Нет прав: …»; изменение `stock` без движений той же пачки — отказ; правка или удаление старой записи `moves` — отказ; движение вида, на который нет права, — отказ; неизвестный ключ — только `admin`
- [ ] G01: инженер и главный инженер — `Clients.create`/`update`, `Feed.comment` к сделке, `Acts.plan`/`done` по сделке отказывают; в интерфейсе у них нет кнопок «Новый клиент», «Изменить», поля комментария и «Запланировать» в ленте сделки; `Guard` такие пачки отвергает; менеджер с `dealsEdit` по-прежнему может
- [ ] `seedBase()` в `20-model.js`: 9 ролей с доборами прав РОП и водителя, воронки, отделы, юрлица, города, причины отказа, настройки, каталог; ни одной записи `demo`, людей нет, сделок, лидов, клиентов, задач, поставок, отправок, уведомлений, ленты нет; `seed()` = `seedBase()` + демо, его тесты не меняются
- [ ] `node tools/build.js && node --test tests/` — зелёный, 417 тестов прототипа на месте
