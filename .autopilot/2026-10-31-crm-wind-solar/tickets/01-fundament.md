## Что должно заработать

Прототип v2 (`crm-wind-solar.html`, один файл на 1388 строк) разложен по исходникам `src/`. Собирается командой `node tools/build.js` в тот же один файл и работает как раньше: все разделы v2 открываются, приёмка с фото меняет остатки, резервы, уведомления и сообщения клиентам.

Поверх этого — основа для всех следующих тасков:
- **Сохранение.** Накликанное переживает перезагрузку. В настройках есть «Сбросить данные прототипа».
- **Роли.** Семь ролей фирмы, права — данными.
- **«Кто я».** Выбирается конкретный человек, а не первый с ролью.
- **Воронки.** Этапы хранятся по id, а не по номеру.
- **Уведомления.** Прочитанность хранится по людям, получатели заданы одной картой.
- **Тема.** Переключатель темы в шапке и в «Настройках».
- **Логотип** wind-solar с сайта.

## Критерии приёмки

- [ ] Есть `src/`, `tools/build.js`, `tools/serve.js`, `tests/load.js`. Команда `node tools/build.js && node --test tests/` проходит. `crm-wind-solar.html` собран из `src/`, в начале файла комментарий «собрано из src/, руками не править».
- [ ] Сборка встраивает `assets/windsolar-logo.png` вместо `.mark`. Логотип читается в светлой и в тёмной теме (в тёмной — на светлой подложке).
- [ ] Каждый раздел v2 открывается и делает то же, что в v2. Приёмка поставки с фото увеличивает остаток, переводит резервы, рождает уведомления и сообщение клиенту. Проверка — тест на `seed()` через ядро и вид.
- [ ] Роли — данные `S.roles`: Директор, Менеджер B2B, Менеджер B2C, Логист, Кладовщик, Главный инженер, Инженер. Права по умолчанию — как в «Решениях по реализации» спецификации. У главного инженера и инженера матрица одинаковая. Новые права: `mail`, `leads`, `dealsAll`, `settings`. Права директора не снимаются.
- [ ] Демо-команда покрывает все семь ролей, в ней не меньше двух менеджеров каждого типа. У инженеров есть поле «специализация: проектировщик / монтажник». Переключатель «Кто я» перечисляет **каждого** человека с ролью. «Мои задачи» и уведомления — этого человека.
- [ ] Раздел без права не показан в меню. Прямой переход в такой раздел показывает «нет доступа» и кнопку «На главный экран».
- [ ] Задачи, сделки и поставки хранят `pipeId` и `stageId`. Переименование, вставка и удаление этапа в `Pipes` не ломают ни одну запись: тест. Воронки по умолчанию — из `interfaces.md`, с флагами `arrived` и `final`. «Закрыто» везде определяется флагом `final`, номеров этапов в коде нет.
- [ ] `Notify.RECIPIENTS` — единственное место, где событие сопоставлено ролям. Прочитанность хранится по людям: два менеджера читают уведомления независимо (тест).
- [ ] Переключатель темы «светлая / тёмная / как в системе» есть в шапке и в «Настройках → Внешний вид». Выбор ставит `data-theme` на `<html>` и запоминается.
- [ ] Раздел «Настройки» с реестром вкладок `SETTINGS_TABS`. В нём вкладки «Внешний вид» и «Данные»; в «Данных» — «Сбросить данные прототипа» с подтверждением.
- [ ] Сохранение: создал задачу или резерв, перезагрузил — всё на месте; «Сбросить» возвращает исходное. Даты переживают сохранение (тест `Store`). Если браузер не дал места, остальное сохраняется без фото, а фото помечаются «не сохранено — мало места в браузере».
- [ ] На ширине 375 px нет горизонтальной прокрутки страницы.
- [ ] Каждый новый тест может покраснеть: исполнитель портил проверяемое число и видел красный прогон.
