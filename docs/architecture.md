# Архитектура

Выжимка из договора границ сборки, имена сверены с кодом. Почему так решили — `docs/adr/`, слова предметной области — `CONTEXT.md`.

## Поток данных

- `tools/build.js` склеивает `src/page.html`, `src/css/*.css`, `src/js/*.js` (по имени файла, по возрастанию, в одну функцию с `'use strict'`) и `assets/windsolar-logo.png` (data-URI на место `{{LOGO}}`, место ровно одно) в один `crm-wind-solar.html`.
- Состояние — одна переменная `S` (`let S` в `src/js/50-shell.js`, схема `v:3`). Запуск (`90-boot.js`): `S = startState()` — сохранённое из `localStorage['ws-crm-v3']` (`Store.KEY`) или демо `seed()`; затем `render()`.
- Клик или ввод → обработчик из реестра (`A`, `FORMS`, `ON`) → функция ядра меняет `S` → `render()` перерисовывает раздел целиком, меню, карточку и вызывает `save()`; ввод с клавиатуры — через `saveSoon()` (400 мс).
- Хранение: `Store.dump(S)` пишет JSON без `S.ui` (даты — `{$date}`), без товаров снимка каталога (`Catalog.pack`; они восстанавливаются из констант `CATALOG` и `STOCK_SNAPSHOT`). Не влезло — выкидываются фото приёмки и файлы заявок по одному, сначала новые и крупные.
- `Store.load(raw)` отдаёт `null` при чужой `v` или `rev` ≠ `Store.REV` — тогда берётся `seed()`. `S.ui` (открытая карточка, вкладки, фильтры) не сохраняется.
- `seed()` = база + шаги `SEEDS` по порядку номеров файлов; каждый раздел сеет своё демо.

## Границы модулей

- Ядро (`30`–`43`): `const Имя = (() => { …; return { … }; })()`. Функции принимают состояние первым аргументом `st`, не трогают DOM, `S`, `localStorage`; время приходит аргументом `now`. Проверяется на маленьком состоянии из теста.
- Исключение: `41-feed.js` — ядро `Feed` плюс вид ленты (`feedHtml`, `actNextHtml`, свои `A` и `FORMS`).
- Модель (`20-model.js`): справочники, `seed()`, помощники над `S` (`can`, `me`, `product`, `stockOf`).
- Виды (`50`–`70`): функции `S → HTML-строка` (`v*`, `d*`, `m*`, `*Html`), состояние не меняют, текст из данных идёт через `esc()`. Состояние меняют только `A`, `FORMS`, `ON` и ядро.
- Порядок склейки = номер файла: код верхнего уровня при загрузке видит лишь то, что объявлено раньше; вызовы внутри функций порядка не требуют.

## Реестры — как раздел подключается

Раздел регистрируется в своём файле, чужих не правит (ADR 0002). Пустые реестры объявлены в `50-shell.js`, кроме двух.

| Реестр | Что кладётся |
|---|---|
| `NAV` | `NAV.push({id, label, icon, group, order, hint, ok, badge?})`; группы `GROUPS`, в группе не больше `MAX_GROUP` пунктов |
| `VIEWS` | `VIEWS.<id> = () => html`, `id` как у `NAV` |
| `DRAWERS` | `DRAWERS.<тип> = id => ({kind, title, sub, body})` или `null`; открывает `openDrawer(тип, id)` |
| `MODALS` | `MODALS.<тип> = id => html`; открывает `openModal(тип, id)` |
| `A` | `A['<act>'] = (el, e) => …` — клик по `data-act` |
| `FORMS` | `FORMS['<form>'] = form => …` — отправка `<form data-form>` |
| `ON` | `ON.input['<key>']`, `ON.change['<key>'] = (el, e) => …` — поля с `data-on`, затем `saveSoon()` |
| `SETTINGS_TABS` | `SETTINGS_TABS.push({id, label, order, ok, render})` — объявлен в `59-settings.js` |
| `SIMS` | `SIMS.push({id, label, run})`, `run` → `{text, view, id?}` — кнопки «Пульта проверки» (`64-sims.js`) |
| `SEARCH` | `SEARCH.push({kind, label, find: q => [{title, sub, open}], order?})`; право и видимость проверяет сам `find` |
| `SEEDS` | `SEEDS.push(st => { … })` — демо раздела; объявлен в `20-model.js` |

## Соглашения

- **Одна величина — одна функция ядра**, экран и карточка зовут её, копию формулы не заводят (ADR 0004):
  - остаток и «свободно» — `Stock.summary`; «ждёт приёмки» — `Ships.awaitingReceipt`;
  - сумма сделки — `Deals.total`, сумма списка — `Deals.sumOf`;
  - право — `Perms.can`; кому уведомление — `Notify.RECIPIENTS`, создание — `Notify.push`.
- **Видимость сделок — только `Leads.dealsVisible(st, personId)`** (ADR 0005): список, поиск, клиент, лента, плитки главного экрана (сводка фирмы по праву `firm` считает все сделки). Лиды — `Leads.visible`.
- **Склад меняет только `Stock.move`** (приход, отгрузка, бой, перемещение): остаток и журнал `moves` пишутся вместе. Резерв — `Stock.reserve`, `unreserve`, `release`; списание при продаже — `Stock.sell`, она идёт через `move`.
- **Воронки — данные через `Pipes`** (ADR 0003): `S.pipelines`, виды `Pipes.KINDS` (tasks, deals, leads, ships, dispatch). Запись хранит id этапа, не номер; «закрыто» — флаг `final`, «прибыло» — `arrived`. Этап меняют функции владельца вида: `Leads.move`, `Deals.move`, `Ships.setStage`, `Dispatch.setStage`.
- **Роли и права — данные** (`S.roles`, `S.people[].role`); неизвестное право не открывает ничего.
- **Отправки (`Dispatch`) — не поставки (`Ships`)** (ADR 0006): свои данные `S.dispatches`, своя воронка.
- Нет данных — `null` или `'_'` в данных и «нет данных: <что>» на экране, не 0.
- Поменялась форма записей — поднять `Store.REV` (последствия — в `AGENTS.md`).
