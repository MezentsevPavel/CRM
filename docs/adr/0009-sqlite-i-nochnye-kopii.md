# 0009. База — SQLite на том же сервере, копии — ночные, там же

## Контекст

Нужна сохранность данных при перезапуске (R03.2) и ежедневные копии (R08). В правилах проекта ничего не ставится, кроме Node 24 и Caddy. Раунд 1, «ок»: копия на том же сервере, 30 последних; копия вне сервера отложена.

## Решение

Данные лежат в SQLite (встроенный модуль Node 24): документы по `key`/`id` с версией, отдельно — номер правки, пользователи, сеансы, файлы, журнал правок. Каждую ночь в 03:00 по часовому поясу сервера делается копия базы целиком; хранятся 30 последних. Директор видит список в «Настройках → Копии», скачивает любую, делает копию сейчас и восстанавливает базу из копии: сперва делается копия текущей, потом база заменяется. Файлы в копии не входят: удалённый из записи файл лежит ещё 30 дней (брошенный — 7), поэтому любая из 30 копий согласована с файлами на диске.

## Почему

- **Копия вне сервера** (облако, второй сервер) — отвергнута на этот этап: нужен отдельный аккаунт, которого нет. Совет «включить платный бэкап хостера» — в инструкции вместо неё.
- **Архив всех файлов одной кнопкой** — отвергнут: копии по брифу — копии базы; файлы защищены 30-дневным хранением и бэкапом хостера.
- **Копировать файлы вместе с базой** — не нужно: файлы не перезаписываются, а удалённые не стираются 30 дней.
- **Часовой пояс копии** — допущение: `Asia/Irkutsk` по умолчанию, потому что часы той машины показывают +08:00; директор часовой пояс не называл. Правится в настройке службы.

## Последствия

- Если умирает сам сервер, вместе с ним умирают и копии. До настройки бэкапа хостера (совет в инструкции) данные не защищены от потери машины.
- Тридцать копий — это ровно 30 дней истории: ошибку, замеченную позже, откатить уже нельзя.
- Файлы копируются только косвенно: брошенный файл исчезает через 7 дней, так что файл, загруженный и не прикреплённый, из копии не восстановить.
- Модуль `node:sqlite` привязывает сервер к Node 24; обновление Node придётся проверять.
- Форма записей в серверной базе данные не стирает никогда (в отличие от браузера и `Store.REV`): несовпадение ревизии — миграция или отказ запуска с понятным текстом. Миграций пока нет.
- Восстановление перезагружает вкладки у всех, кто в этот момент работает.
