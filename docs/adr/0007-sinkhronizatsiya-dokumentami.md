# 0007. Браузер и сервер синхронизируются документами, обработчики экранов не переписываются

Заменяет часть 0001: в рабочей версии данные хранит сервер, а не `localStorage`. Демо одним файлом остаётся как в 0001.

## Контекст

В прототипе 114 из 249 обработчиков меняют данные; 60 из них (53 %) правят `S` напрямую, без ядра, и для задач, приёмки, поставок и справочников ядра нет вовсе. Нужна общая база на всех (R03) с правами на запись (R05) и без потери правки при одновременной работе (R20i).

## Решение

Состояние `S` режется на документы: запись массива — по `id`, запись словаря (`stock`, `aside`) — по ключу, остальные ключи верхнего уровня — целиком. Личное (`me`, раздел, тема, черновик приёмки) в общую базу не уходит. После каждого сохранения браузер сравнивает `S` с последней копией, подтверждённой сервером, и шлёт пачку изменённых документов. Сервер делает трёхстороннее слияние с текущей версией (поля объекта — по отдельности, записи с `id` — по `id`), проверяет права и записывает пачку целиком или не записывает ничего.

## Почему

- **Команды в ядро** («создать сделку», «принять поставку» вместо правки `S`) — отвергнуто как дорогое: пришлось бы переписать 60 прямых обработчиков и завести ядро для всего, чего в нём нет. Выигрыш был бы в том, что права проверяются на месте, но правила записи всё равно пишутся заново для сервера, так что экономии на правилах нет.
- **Заменять на сервере весь `S` целиком** («последний сохранивший победил»; вывод из R20i, в спецификации отдельно не обсуждалось) — отвергнуто: две правки разных полей одной записи в одну минуту съели бы одна другую молча. Слияние по полям оставляет обе; на одном поле проигравший получает тост «показана свежая версия, повтори» (R20i).

## Последствия

- Каждый новый ключ в `S` обязан быть отнесён к виду (массив, словарь, целиком, личное) и получить правило записи. Неизвестный ключ сервер принимает только от директора.
- Экраны остаются как есть, но сервер видит не намерение («принять поставку»), а результат — набор изменённых документов. Осмысленность набора проверяют правила записи; чего правила не предусмотрели, то пройдёт.
- Слияние идёт с урезанной копией человека (чтобы вырезанные цены и скрытые сделки не записались обратно). Правка места, которого человек не видит, не применяется молча.
- Одну запись нельзя «смержить» там, где изменили одно поле по-разному, — это конфликт, и правку приходится повторять руками.
- Часть побочных записей, которые прототип делает при отрисовке (напоминания, «лид ждёт»), в рабочей версии делает только сервер.
