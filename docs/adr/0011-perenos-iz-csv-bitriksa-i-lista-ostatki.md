# 0011. Перенос — директор загружает CSV листа «Остатки» и CSV Битрикса, резервы переходят с примечанием

Заменяет часть «Договорились» прошлой сборки: остатки — не снимок на 31.10.2026, а свежая выгрузка в день переезда; резервы из колонки «Резерв» переносятся (слово директора 2026-11-01).

## Контекст

Настоящие остатки и клиенты нужны в базе (R13, R14). Клиентов можно взять из Битрикса, остатки — из Google-таблицы «Выгрузка с корса общая», лист «Остатки». Образца файла листа в репозитории нет. Интеграция с Битриксом — следующий этап (R15).

## Решение

В «Настройки → Перенос» директор загружает CSV листа «Остатки» и CSV контактов и компаний Битрикса. Браузер показывает предпросмотр: сколько товаров, склеено с каталогом, остатков, резервов, неразобранных клеток; новых клиентов, объединено с заведёнными, пропущено, нераспознанных колонок. Подтверждает директор — и сервер исполняет загрузку той же функцией. Кодировка и разделитель определяются сами. Товары листа без пары в каталоге узнаются по нормализованному названию, поэтому повторный перенос заменяет прошлый и не удваивает остатки. Остаток ложится в журнал склада движением «Ввод остатков». Клетка «Резерв» разбирается на количество и примечание-имя: «36шт автоношкин, 64 Алексей Н.» — два резерва без сделки. Клиент сливается с уже заведённым по ИНН, телефону или почте. CSV клиентов на сервере не сохраняется.

## Почему

- **Снимок 31.10.2026 внутри сборки** — отвергнут: остатки устареют к дню переезда. В рабочей базе до переноса остаток — «нет данных: остаток».
- **Имена клиентов из «Резерва» не переносить** (прежняя договорённость) — заменено словом директора 2026-11-01: количество важно, а текст ячейки сохраняется примечанием.
- **Связывать резерв со сделкой по имени** (вывод сборки, в спецификации отдельно не обсуждалось) — отвергнуто: по тексту «автоношкин» сделку не найти, а выдумывать связь нельзя.
- **Загружать из Google-таблицы и Битрикса напрямую** — отвергнуто для этого этапа: это внешняя интеграция («Битрикс — следующий этап»), и она требует доступа, которого нет.
- **Положить выгрузку клиентов в репозиторий или сборку** — отвергнуто: персональные данные клиентов не должны проходить через git и сборку (R14.2).
- **Связать контакт с записью компании** — отвергнуто: у клиента-человека остаётся текст «Компания, должность», автоматической связи нет.

## Последствия

- Колонки листа «Остатки» взяты по описанию, а не по образцу файла: тесты — на искусственном CSV той же формы. Первая настоящая выгрузка может показать несовпадения — они попадут в «неразобранные».
- Товар узнаётся по названию: переименование в таблице между двумя переносами даст новый товар, а не обновит старый. Из 208 строк прошлого снимка склеилось с каталогом 16, остальные стали товарами «нет в каталоге».
- Колонки Битрикса опознаются по стандартным русским названиям; нестандартные уходят в «нераспознанные».
- Повторный перенос заменяет остатки и резервы, помеченные как пришедшие с прошлым переносом; резервы, заведённые людьми, по спецификации не затрагиваются.
- Резервы без сделки видны как «нет данных: сделка» и снимаются по праву `reserve`.
- Живой связи с Битриксом нет: у клиента лишь хранится `bitrixId` для будущей.
