# 0001. Прототип — один HTML-файл из `src/`, данные хранятся в браузере

## Контекст

Директор хочет открыть и прокликать CRM «в браузере», пока «с точки зрения дизайна» (R17, R18), по тому же адресу артефакта, что и v2. v2 — рукописный файл в 1388 строк (137 939 байт), в браузере он сохранял только роль и раздел.

## Решение

CRM — одна HTML-страница без зависимостей. Исходники лежат в `src/` (js и css по файлам, номер в имени задаёт порядок сборки), `tools/build.js` склеивает их в `crm-wind-solar.html`. Собранный файл руками не правится, тест сверяет его со сборкой.

Всё, что меняет пользователь, сохраняется в `localStorage` под одним ключом с номером версии схемы (`Store.KEY`, `Store.REV`). Каталог и остатки — константы-снимки внутри файла: они не меняются и в браузер не пишутся. Сохранение обёрнуто в `try/catch`, без него страница тоже работает.

Нужны только браузер и Node с `node:test`. Внешний адрес в странице один — Google Fonts. Логотип вшит в страницу, карта маршрута — свой SVG. Письма, сообщения клиентам, лиды из Битрикса24 и статусы перевозчика — имитация, наружу ничего не уходит.

## Почему

- **Настоящий сервер с общей базой и входом по паролю** — отложен. Директору сначала нужно увидеть и прокликать; сервер, настоящая почта, Битрикс24, сайт и трекинг перевозчиков названы в спецификации «следующим этапом» (раунд 1, «Кликабельный прототип»). Один файл открывается по ссылке артефакта без сервера.
- **Рукописный единый файл, как v2** — отвергнут как способ писать, но сохранён как результат. В v2 всё лежит в одной функции, расчёт остатков собран в трёх местах, экраны меняют состояние при отрисовке (слабые места 3, 4, 14 в `notes.md`). Ядро нельзя проверить отдельно от экранов. Исходники по файлам дают ядро без DOM, которое `tests/load.js` исполняет в `node:vm`, и по своей зоне файлов на каждый таск. Это вывод из устройства v2 и из таблицы зон, не слова пользователя.
- **Хранить, как в v2 (роль и раздел, остальное в памяти)** — отвергнуто: R59i требует, чтобы накликанное при проверке не пропадало от перезагрузки.
- **Картинки, карты и библиотеки с чужих адресов** — отвергнуты: опубликованная страница их не загрузит (исключение — Google Fonts, как в v2). Зависимости не ставятся по правилу проекта: не хватает — называем, как называется.

## Последствия

- Данные живут в браузере одного человека. Общей базы нет: «всем приходит уведомление» видно только на этом компьютере, а других сотрудников показывает лишь переключатель «Кто я».
- Сохранение чужой версии схемы не читается: `Store.load` отдаёт `null`, берётся `seed()`. Поэтому каждое изменение формы данных поднимает `Store.REV` (к T07 он дошёл до 10), а накликанное в старой версии не переезжает. Миграции старых сохранений в источниках не описаны — нет данных.
- Места в браузере мало. Фото приёмки и файлы заявок могут не влезть: сохраняется остальное, вложение помечается «не сохранено — мало места в браузере». Файл больше 2 МБ не принимается (`FILE_MAX`), при переполнении вложения выбрасываются по одному, сначала новые и крупные. Размер сохранения стережёт тест (порог 340 000 символов на T09).
- Переход на сервер заменит слой сохранения. Ядро для этого отделено по договору: оно не трогает DOM, `localStorage` и `Date.now()`. На настоящем сервере этот договор не проверялся.
- Забытая пересборка не проходит незамеченной: тест сверяет `crm-wind-solar.html` со сборкой из `src/`.
