# 0013. Обновление по кнопке: сервер сам берёт новую версию с открытого GitHub

Дополняет 0012: страница по-прежнему не ходит на внешние адреса; на GitHub ходит сервер, и только по команде директора.

## Контекст

Директор запускает CRM на нескольких компьютерах (рабочий, домашний, позже VPS) и каждый раз копировал папку руками. Просьба 2026-11-12: «кнопка обновить в CRM, чтобы приходило обновление по воздуху». Репозиторий `MezentsevPavel/CRM` был закрытым; на вопрос «как рабочему компьютеру получать обновления» директор выбрал сделать его открытым (его слова), зная, что в нём код, цены каталога и снимок остатков.

## Решение

«Настройки → Обновление» (только право admin): «Проверить обновления» спрашивает GitHub API про последние коммиты ветки master и показывает, что нового с установленной версии; «Обновить» делает копию базы, скачивает архив именно этого коммита, проверяет, что в нём есть сервер и страница, откладывает прежний код в `data/update-backup`, заменяет код (data, тесты и служебные папки не трогаются), записывает версию в `.crm-version` и перезапускает сервер. Перезапуск — выход с кодом 75: его подхватывает systemd (`Restart=always`) или `start.cmd` / `start.sh` (цикл «пока код 75»). Без такой обвязки (признак — `INVOCATION_ID` или `CRM_SUPERVISED=1`) сервер ставит код и просит перезапустить его вручную. Открытые вкладки узнают о новой версии страницы из события `build` и перезагружаются сами. Код — `server/updater.js`, экран — `src/js/76-update.js`.

## Почему

- **Закрытый репозиторий с ключом доступа** — отвергнут директором: ключ надо хранить на каждом компьютере.
- **`git pull` на сервере** — отвергнут: на рабочем компьютере папку копируют без `.git`, а git там может не стоять. Архив качается обычным https, распаковывает системный `tar` (есть в Windows 10+ и Ubuntu).
- **Автообновление без кнопки** — отвергнуто: обновление перезапускает CRM у всех, решает директор и когда.
- **Своя распаковка zip в Node** — отвергнута: в Node 24 нет разбора zip без внешней зависимости, а зависимости молча не ставятся.

## Последствия

- Любой, кто может писать в репозиторий, может прислать код на все серверы CRM. Доступ к GitHub-аккаунту директора защищать так же, как доступ к серверу.
- Репозиторий открытый: код, цены каталога и снимок остатков видны всем. Пароли, настоящие CSV клиентов и базы в нём не лежат.
- Обновление зависит от интернета на сервере; без него кнопка пишет «Нет связи с GitHub», работа CRM не страдает.
- Копия базы не включает файлы и фото; при сбое посреди замены код возвращается из `data/update-backup` сам, при «странной» работе новой версии — руками.
- В рабочей копии для разработки (рядом `.git`) кнопка ничего не заменяет: там код обновляют через git. На Ubuntu с `deploy/update.sh` кнопка работает, только если папка кода доступна на запись службе — проверено не было (на VPS ещё не ставили).
- `start.cmd` / `start.sh` нужно использовать вместо `node server/main.js`, чтобы обновление проходило без ручного перезапуска.
