# Как поставить CRM на свой сервер

Инструкция для директора, без программирования. Нужно один раз арендовать сервер и домен, потом выполнить несколько команд.
Всё делается с вашего компьютера с Windows. Время: около часа, из них ожидание — пока домен «разойдётся» по интернету.

В тексте есть два места, которые вы заменяете своими данными. Их я не знаю и не придумываю:

- `<домен>` — адрес, по которому будет открываться CRM, например `crm.вашфирма.ру` (нет данных: какой домен вы возьмёте);
- `<IP-сервера>` — четыре числа через точку, которые пришлёт хостер (нет данных: какой сервер вы арендуете).

## 1. Что арендовать

**Сервер (VPS) в России.** Данные сотрудников и клиентов должны лежать в России (152-ФЗ), поэтому хостер российский.
Заказываете «виртуальный сервер» с такими параметрами:

| Что | Сколько |
|---|---|
| Система | Ubuntu 24.04 |
| Память | 2 ГБ |
| Диск | 30 ГБ |
| Процессор | 1–2 ядра |

Хостер сообщит (письмом или в личном кабинете) **IP-сервера** и пароль пользователя `root`. Сохраните их.

**Домен.** Любой, который вы арендуете у регистратора. Понадобится один адрес, например `crm.вашфирма.ру`.

**Совет: включите платное резервное копирование у хостера** (у большинства хостеров это отдельная опция в кабинете сервера; цену смотрите у выбранного хостера).
CRM делает свои копии базы каждую ночь, но лежат они на том же сервере: если сервер пропадёт целиком, пропадут и они.
Копия хостера хранится отдельно.

## 2. Направить домен на сервер

В кабинете регистратора (там, где вы арендовали домен) откройте управление DNS и создайте запись:

- тип: **A**
- имя: `crm` (если домен `crm.вашфирма.ру`) или `@` (если CRM будет на самом `вашфирма.ру`)
- значение: `<IP-сервера>`

Запись расходится от пяти минут до нескольких часов. Проверить на своём компьютере: откройте PowerShell и выполните

```
nslookup <домен>
```

В ответе должен появиться `<IP-сервера>`. Пока там другое — подождите.

## 3. Упаковать CRM и отправить на сервер

Откройте PowerShell **в папке проекта CRM** (в проводнике: папка проекта → в адресной строке напишите `powershell` → Enter).

Упаковка (одна команда; архив ляжет на папку выше):

```
tar -czf ..\crm.tar.gz --exclude=.git --exclude=.claude --exclude=.autopilot --exclude=data --exclude=tests --exclude=.env* .
```

Отправка на сервер:

```
scp ..\crm.tar.gz root@<IP-сервера>:/root/
```

Первый раз компьютер спросит про отпечаток сервера — напишите `yes`. Потом попросит пароль `root` (при вводе он не виден — это нормально).

## 4. Войти на сервер

```
ssh root@<IP-сервера>
```

Пароль тот же. Строка слева поменяется на что-то вроде `root@...:~#` — вы на сервере. Дальше команды выполняются там.

## 5. Три команды установки

```
mkdir -p /root/crm && tar -xzf /root/crm.tar.gz -C /root/crm
cd /root/crm
bash deploy/install.sh <домен>
```

Скрипт сам ставит всё нужное: Node 24, Caddy (он сам получает и продлевает сертификат https и перенаправляет `http` на `https`),
заводит службу CRM, которая сама запускается при включении сервера и перезапускается при сбое, открывает порты 22, 80 и 443,
собирает страницу. Ничего из интернета, кроме самих программ, он не берёт: шрифты уже внутри страницы.

Скрипт задаст вопросы:

1. Если домен ещё не указывает на сервер, предупредит и спросит «Продолжить?». Лучше ответить `нет`, дождаться (раздел 2) и запустить заново.
2. **Имя, логин и пароль директора.** Пароль не короче 8 символов, при вводе он не виден, его просят ввести дважды.
   Это ваш вход в CRM, запомните его.

Минуты через две-пять скрипт напишет «Готово». Повторный запуск `install.sh` безопасен: готовое он пропускает, базу и директора не трогает.

## 6. Первый вход

Откройте в браузере `https://<домен>` (если страница ещё не открывается — подождите минуту-две, пока Caddy получит сертификат).
Введите логин и пароль директора.

Дальше в самой CRM:

1. **Сотрудники** — заведите людей: имя, отдел, роль, логин. Пароль выдаст CRM один раз — передайте его сотруднику, при первом входе он его сменит.
2. **Настройки → Перенос** — загрузите остатки (файл CSV листа «Остатки») и клиентов (CSV из Битрикса).

## 7. Копии базы и восстановление

- Каждую ночь в 03:00 по времени сервера CRM сама делает копию базы; хранятся 30 последних. Часовой пояс сервера — Иркутск (`Asia/Irkutsk`).
  Если вам нужен другой, на сервере: `systemctl edit --full crm`, измените строку `Environment=TZ=...`, сохраните и выполните `systemctl restart crm`.
- В CRM: **Настройки → Копии** — список копий, «Скачать» (сохраните копию к себе на компьютер хотя бы раз в неделю),
  «Сделать копию сейчас» и «Восстановить». Восстановление заменяет базу для всех сотрудников; перед ним CRM сама сохраняет копию текущей базы.
- Фото и документы в копию базы не входят: они лежат на сервере отдельно, их сохраняет бэкап хостера (раздел 1).
- Если CRM не открывается совсем, на сервере (`ssh root@<IP-сервера>`):

  ```
  crm-admin backups
  crm-admin restore <имя копии из списка>
  systemctl restart crm
  ```

- Забыли пароль сотрудника (или свой) — на сервере: `crm-admin reset-password <логин>`. Новый пароль показывается один раз.

## 8. Обновить CRM до новой версии

Данные при обновлении не трогаются: база, файлы и копии лежат отдельно от программы.

1. В CRM: **Настройки → Копии → Сделать копию сейчас** (на всякий случай).
2. На вашем компьютере упакуйте и отправьте новую версию так же, как в разделе 3.
3. На сервере:

   ```
   rm -rf /root/crm-new && mkdir -p /root/crm-new && tar -xzf /root/crm.tar.gz -C /root/crm-new
   bash /root/crm-new/deploy/update.sh
   ```

Скрипт собирает новую версию в стороне, подменяет старую, перезапускает CRM и проверяет, что она отвечает. Если новая версия не запустилась,
он сам вернёт прежнюю.

## Если что-то не так

| Что видно | Что делать |
|---|---|
| Страница не открывается, браузер пишет про сертификат | Домен ещё не указывает на сервер (раздел 2) или прошло меньше пары минут. Проверьте `nslookup <домен>`, подождите |
| «Не удаётся получить доступ» | На сервере: `systemctl status crm` — служба должна быть «active (running)». Журнал: `journalctl -u crm -n 50` |
| Скрипт остановился с «ОШИБКА: …» | Текст ошибки написан по-русски. Исправьте причину и запустите скрипт снова — повторный запуск безопасен |
